# Barnes & Noble Inventory Platform

## Description

Web application for **Barnes & Noble** to monitor book availability across its bookstores and to receive new books into inventory. Bookstores and book stock records come from a simulated backend (json-server). Books come from the **Open Library API**.

## Features

- **Toolbar**: shows the Barnes & Noble logo (Logo.dev Logo API) and the text "Barnes & Noble Inventory Platform", with EN / ES select buttons on the right for switching the language.
- **Sidenav**: a navigation sidebar with the "Bookstore Overview" and "Receive Books" options. It stays open beside the content on wide screens and opens over the content on handsets.
- **Bookstore Overview** (`/bookstores/overview`):
  - Shows the title "Bookstore Overview" and the text "Monitor Book Availability Across Our Stores".
  - The **Store Inventory** section is a responsive grid list of Bookstore Summary cards, two per row on wide screens.
  - Each card shows:
    - Header: the bookstore name.
    - Content: each book with its total copies, adding up all book stock records of the same `bookKey`. Shows "Empty" when the bookstore has no book stocks.
    - Footer: the **Available Titles** indicator (distinct books) and the **Replenishment Required** indicator (distinct books whose total copies are below the bookstore `minimumCopies`).
- **Receive Books** (`/inventory/receipts/new`):
  - A reactive form where the user selects a **specialty**, then a **book** from Open Library (`/subjects/{specialty}.json?limit=50`), and enters the **copies**.
  - Values filled in automatically:
    - The bookstore is chosen from the specialty (there is one bookstore per specialty).
    - `receivedAt` is set to the current date and time.
    - `id` is generated by the backend.
    - `bookKey`, `bookTitle` and `authorName` come from the Open Library `key`, `title` and first `authors[].name`. If a book has no author, "Unknown Author" is used.
  - Validation: copies must be an integer greater than zero and less than or equal to twice the bookstore `minimumCopies`.
  - **Receive** registers the book stock and, once the registration completes, returns to Bookstore Overview, which shows the updated inventory. **Cancel** returns without registering.
- **Page not found**: shown for unsupported routes. It displays the requested path and offers a button to return to Bookstore Overview.
- `/` redirects to `/bookstores/overview`.
- **i18n**: English (default) and Spanish.

## Stack

- TypeScript and Angular 22.2, with stand-alone components
- Angular Material (green / spring-green pre-built palettes, adapted to the Barnes & Noble dark green)
- `@angular/common/http` HttpClient
- `@angular/router`, with semantic routes and child routes per bounded context
- Angular Signals for state management
- `@ngx-translate/core` and `@ngx-translate/http-loader` for i18n
- json-server 0.17.4 as the fake API
- Open Library API as the external catalog, and the Logo.dev Logo API

## Architecture

The project uses domain-driven design with a layered and component-based architecture. Each bounded context has the sub-folders `domain`, `application`, `infrastructure` and `presentation`.

| Bounded context | Responsibility |
| --- | --- |
| `shared` | Base types (BaseEntity, BaseAssembler, BaseApi, BaseApiEndpoint), the `Specialty` shared kernel, Logo.dev API, layout with toolbar and sidenav, language switcher, footer and page-not-found view |
| `bookstores` | Bookstores and book inventory (`Bookstore`, `BookstoreInventory`), the `BookstoresStore`, the Bookstore Overview view and the Bookstore Summary card |
| `inventory` | Book stocks (`BookStock`), the `InventoryStore` and the Receive Books view |
| `catalog` | Books from the Open Library API (`Book`), the `CatalogStore` and the Book Summary component |

Design patterns applied: Request/Response, Resource, Assembler, Api, Endpoint and Store.

## Configuration

1. Install the dependencies:

   ```bash
   npm install
   ```

2. Start the fake API. It is available at `http://localhost:3000`:

   ```bash
   cd server
   npx json-server --watch db.json
   ```

   Endpoints:
   - `http://localhost:3000/bookstores`
   - `http://localhost:3000/book-stocks`

3. In another terminal, start the application and open `http://localhost:4200`:

   ```bash
   ng serve
   ```

All URLs and paths are defined in `src/environments/environment*.ts`.
